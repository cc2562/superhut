## 修复：历史学期课表第一周仍显示当前日期

- **现象**：切换历史学期后，周视图标题「第 1 周」但日期仍是今天的日期。
- **根因**：前端 `render` 里 `date = calculateSchoolWeek(...) 落在 [1,maxWeek] ? today : first` 依赖「今天算出来
  的第几周」判断，历史学期 firstDay/maxWeek 与实际日历不符时误判为「今天在当前学期内」，于是显示 today。
- **修复（测试用途，最小改动）**：data 加 `currentSemesterId`（ensureSemesters 从 `semesters` 里取 `current` 学期
  的 id）。`render` 里若 `semesterId !== currentSemesterId`（历史学期）则 `date = first`（直接锚定第一周），
  跳过 calculateSchoolWeek 计算；当前学期仍走原「今天 or 第一周」逻辑。
- CI 全绿。注意：`miniprogram_npm` 快照问题（见 8-21）仍需在微信开发者工具「构建 npm」后真机验证。

## 修复：记住课表页选择的学期（重进不再重置为最新学期）

- **现象**：切换历史学期后，重新进入小程序，学期选择丢失、又变回最新学期。
- **修复**：storage 加 `timetable_semester_v1` key + `timetableSemester()`/`saveTimetableSemester(id)` 方法；
  `onSemesterChange` 选择时保存；`ensureSemesters` 恢复时优先读 `storage.timetableSemester()`（若该 id 已不在
  semesters 列表里则回退 current 学期）。首次进入无保存仍默认最新学期。
- CI 全绿。仅前端 2 文件（storage.ts + timetable/index.ts）。

## 修复：历史学期课表「课程节次格式发生变化」报错

- **现象**：查历史学期课表时后端持续抛「课程节次格式发生变化」。
- **根因**：`real-academic.provider.ts` 的 `mapNormalWeek` 对 `classTime` 做严格 `^\d{5}$` 校验，历史学期数据里
  存在非 5 位（空值/单节 3 位等）就 throw `ACADEMIC_UPSTREAM_CHANGED`。而 Flutter 版 `getCourse.dart:getSingleClass`
  是容错的：`classTime.length < 3` 跳过 + `int.parse` 失败 catch 后 continue。
- **修复**：对齐 Flutter 容错——`length < 3` 跳过；`Number()` 解析 weekday/startSection/endSection，任一
  `!Number.isInteger` 则跳过该课程；不再 throw。测试 `rejects malformed week fields` 改为 `skips malformed
  classTime and keeps parsing valid courses`。
- CI 全绿（44 服务端测试）。真机仍需在微信开发者工具「构建 npm」后验证历史学期真实数据。
