# 2026-08-23

## 微信小程序接入阿里云验证码 2.0（V3 架构）

### 目标
为「登录教务系统」和「刷新课表」两个独立场景接入阿里云验证码，验证通过前阻断登录/刷新。

### 已确认的产品决策
1. **登录流程内不二次验证**：登录验证码通过后，登录成功紧接着的首次课表同步视为登录流程一部分，不弹「刷新课表」验证码。实现：登录接口服务端顺带完成首次课表刷新并返回课表。
2. **静默自动重登保留且豁免验证码**：`api.ts` 的「记住密码→token 过期自动重登」保留，不弹码。实现：新增独立接口 `/v1/auth/academic/relogin`，服务端强校验「请求学号 == 已绑定学号」+ 保留登录限流。
3. **fail-closed**：验证码服务故障时拒绝登录/刷新，不降级放行。
4. 两个 SceneId 与 RAM AccessKey 尚未拿到，先用占位符（`REPLACE_WITH_LOGIN_SCENE_ID` / `REPLACE_WITH_REFRESH_SCENE_ID` 在 `services/captcha.ts`；后端环境变量见 `config.ts`）。

### 关键改动
- **前端**：`app.json` 声明 `AliyunCaptcha` 插件（provider `wxbe275ff84246f1a4`）+ 全局 usingComponents `aliyun-captcha`；新增 `services/captcha.ts`（`verifyCaptcha(host, scene)` 返回 Promise<string>，setData 渲染完成后 `plugin.show()`）；登录页/我的页/课表页接入验证码并挂载 `<aliyun-captcha>`；`api.ts` 的 `academicLogin`/`refreshTimetable` 增加 `captchaVerifyParam`、静默重登改走 relogin、`toastRequestError` 新增 CAPTCHA 三错误码文案。
- **后端**：新增 `server/src/captcha/captcha.service.ts`（**零依赖 HTTPS 原生调用 + ACS3-HMAC-SHA256 签名**，未用官方 SDK，避免云托管 Node 24 依赖链问题）；`config.ts` 加 6 个验证码环境变量 + real 模式 required；`auth.controller.ts` login 校验验证码 + 新增 relogin 接口；`auth.service.ts` 拆出 `performLogin`，`loginAcademic` 顺带刷新课表（失败降级）、新增 `reloginAcademic` 同学号校验；`academic.controller.ts` refresh 校验验证码（captchaVerifyParam 改从 body 解析，semesterId 不再走 query）；`openapi.controller.ts` 同步 schema。
- **契约**：`api-contract` 新增 3 错误码（CAPTCHA_REQUIRED / CAPTCHA_VERIFY_FAILED / CAPTCHA_SERVICE_UNAVAILABLE）+ `AcademicReloginRequestSchema` + `TimetableRefreshRequestSchema` + `AcademicLoginResponseSchema`。

### 关键坑
- `captchaVerifyParam` 设为**可选**（schema），controller 里手动判空抛 `CAPTCHA_REQUIRED`；否则缺失时会被 Zod 映射为 `VALIDATION_ERROR`，无法给独立错误码。
- `Record<string,string>` 下标访问返回 `string | undefined`，fetch headers 不接受，需用显式变量（`action`/`version`）。
- `AcademicLoginResponseSchema` 引用了后面才定义的 `AcademicBindingSchema`/`TimetableSchema`，const 暂存死区报错，需移到 `TimetableSchema` 之后。
- 前端插件 API：`requirePlugin('AliyunCaptcha')` 返回 `show()` 方法；`success` 回调第一参数即 `captchaVerifyParam`；组件 `props` 通过 setData 传 `{SceneId, mode:'popup', success, fail}`；setData 的 callback 是「渲染完毕回调」，用它保证组件挂载后再 `show()`。

## 修复验证码首次黑屏 + 取消提示（同日追加）

- **黑屏根因**：`verifyCaptcha(host, scene)` 里「setData 挂载组件 → 回调里立即 `plugin.show()`」，组件挂载与 show 之间无时间差，插件（requirePlugin 实例）尚未完成初始化就弹出 → 第一次只显示黑色蒙层、无验证码内容，第二次插件已初始化才正常。
- **修复**：改为官方推荐模式——页面 `onLoad` 预挂载组件（`mountCaptcha(host, scene)` 设 `loadCaptcha: true + pluginProps`），用户点击时才 `verifyCaptcha()`（只 `plugin.show()`）。每次验证结束（success/fail/onClose）立即 `reloadCaptcha`（先 false 再 true 重挂），为下次验证预初始化，避免重挂后再次黑屏。
- **onClose 语义**：插件 `onClose(isVerify)` 回调——`isVerify=true` 是验证成功触发的关闭（success 已处理，忽略）；`isVerify=false` 是用户主动关闭（取消），reject `CaptchaCancelledError`。
- 刷新课表取消验证 toast「已取消验证」（我的页 + 课表页）；登录页取消仍静默。
- 登录形态保持弹出式（用户确认不改内嵌式；小程序插件 V3 mode 只支持 popup，无 embedded）。
- 关键点：`captcha.ts` 用模块级 `pendingResolve/pendingReject` 桥接 Promise（验证码弹窗是全局单例，同时只有一次流程）。

## 修复「验证通过后仍提示验证未通过」（同日再追加）

- **现象**：前端验证码通过（success 拿到 captchaVerifyParam），后端校验后仍报「验证未通过」，登录/刷新都如此。
- **根因**：`CaptchaService` 自实现 ACS3-HMAC-SHA256 签名**漏签 `content-type` 头**。阿里云 V3 签名规范——「除 Authorization 外的所有请求头只要存在就必须签名」，POST form 必带 `content-type: application/x-www-form-urlencoded`；漏签 → 签名不匹配 → 阿里云返回**无 `Result` 字段**的签名错误 → 旧代码 `json.Result?.VerifyResult !== true` 把「无 Result」误判为验证失败，抛 `CAPTCHA_VERIFY_FAILED`。
- **修复**：① `content-type` 纳入 `signed` 表参与签名；② 错误分类——`VerifyResult === false`（真实验证失败 F012/F008/F015 等）→ `CAPTCHA_VERIFY_FAILED`；其余（签名/权限/欠费/HTTP 非 200）→ `CAPTCHA_SERVICE_UNAVAILABLE`，并 Logger 记录阿里云 `code/message/verifyCode`。
- **教训（重要，复用）**：阿里云 V3 签名 SignedHeaders 必须包含请求中实际存在的所有 `x-acs-*` + `host` + `content-type`；「无 Result 字段」≠「VerifyResult=false」，要分开处理，否则会把服务端签名/配置错误误报成用户验证失败。

## 修复「验证服务不可用」：签名已正确，问题在 AccessKey 配置（同日三度追加）

- **现象**：修复 content-type 签名后，错误从「验证未通过」变成「验证服务不可用」（`CAPTCHA_SERVICE_UNAVAILABLE`），说明已正确进入「无 Result」分支。
- **定位手段（关键）**：用**假 AccessKey** 直接调 `VerifyIntelligentCaptcha` 探测，返回 `InvalidAccessKeyId.NotFound`（HTTP 404）——**而非 `SignatureDoesNotMatch`**。这证明签名实现是**正确**的（阿里云已通过签名验证、走到查 AccessKey 阶段），问题出在 AccessKey 配置本身。
- **根因方向**：AccessKey ID/Secret 配错（复制带空格/换行）、RAM 子账号未授权 `AliyunYundunAFSFullAccess`（返回 `Forbidden.RAMUserAccessDenied`）、或 AccessKey 不存在/已删除。
- **修复**：把阿里云返回的 `code` 附加到 `CAPTCHA_SERVICE_UNAVAILABLE` 的 message（如「验证服务暂不可用（Forbidden.RAMUserAccessDenied）」），前端 toast 直接可见，免查日志。
- **复用经验**：排查阿里云签名问题时，用假 AK 探测是高效手段——返回 `InvalidAccessKeyId.NotFound`=签名对、AK 错；返回 `SignatureDoesNotMatch`=签名错。签名与 AK 校验有先后顺序，可据此二分定位。
