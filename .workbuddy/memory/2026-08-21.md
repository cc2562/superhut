## 关键坑：vitest forks pool 多文件 exit 1

- server 测试 6 个文件时（3 个 bootstrap NestJS app + 3 个纯单测），默认 forks pool 下 **40 项全过但 exit 1**，
  导致 `pnpm run ci` 失败；5 文件时不触发（竞态）。
- 根因：forks 池下每个 bootstrap 测试文件是独立子进程，NestJS/Fastify app teardown 的 open handle 竞态
  使进程非零退出；threads 池稳定。
- 解法：`server/vitest.config.ts` 加 `test.pool = 'threads'`（已注释说明原因）。改动后 CI 全绿。
- 教训：本仓库 server 用 vitest 默认 forks，但多个测试文件各自 bootstrap NestJS 应用会踩这个坑；
  新增第 3 个 bootstrap 测试文件时触发。以后再加 bootstrap 测试文件，若 CI 偶发非零退出，优先查 pool。

- CI 全绿：64 项测试（6 领域 + 18 客户端 + 40 服务端）。CHANGELOG 已更新。
- 真机回归待真实成绩数据（汇总字段类型、空学期行为已在 fixture 层验证）。

## 微信小程序：教务 Token 过期检测与错误提示区分

- 根因：服务端 `binding.status` 只在登录时设 'active'，从不更新 'expired'。学校业务接口（成绩/考试/课表）
  对过期 token 返回 HTTP 500 + 非 401 code，只有 `/njwhd/noticeTab` 返回 500+code=401。所以 BFF 把业务接口
  的失败映射成 `ACADEMIC_UPSTREAM_UNAVAILABLE`，用户误以为"网络不可用"。
- 解法：`academic.service.ts` 加 `guardUnavailable(userId, token, fn)` + `withToken(userId, fn)` 包装所有查询：
  业务查询遇 `ACADEMIC_UPSTREAM_UNAVAILABLE` 时二次调 `validateToken`(noticeTab)，过期则 `markBindingExpired` +
  抛 `AUTH_ACADEMIC_EXPIRED`；标记后 `tokenFor` 直接抛过期。
- `state.service.ts` 加 `markBindingExpired(userId)`（fixture 改内存 binding.status，真实 UPDATE academic_bindings）。
- **坑**：guardUnavailable 里 `throw AUTH_ACADEMIC_EXPIRED` 若写在内层 try 里会被内层 catch 吞掉，导致返回原
  unavailable。用 `let expired=false; try { expired = !(await validateToken) } catch {}` 规避。
- 文案区分：`ACADEMIC_UPSTREAM_UNAVAILABLE` message "学校服务暂时不可用"→"学校服务器不可用"（明确学校侧），
  与我方 `INTERNAL_ERROR` "服务暂时不可用" 区分。
- 客户端 `toastRequestError` 对 `AUTH_ACADEMIC_EXPIRED` 提示"教务登录已过期"并 setTimeout 后 navigateTo 登录页。
- CI 全绿：68 项测试（6 领域 + 20 客户端 + 42 服务端，新增 token-expiry 2 项 + toastRequestError 2 项）。
- 真机回归待真实过期 token 验证。

## 微信小程序：空教室查询支持任意节次 + 座位数 + 状态条

- 复刻 Flutter `lib/utils/roomapi.dart` + `lib/pages/freeroom/room.dart`。
- **nodeId** = 起止节次各 `padLeft(2,'0')` 拼接（如 0102、0112），范围 1~12 节。之前小程序写死 '0102'。
- **zyjc 解析**：逗号分隔的占用节次区间，每段去掉首字符（如 "10102"→"0102"），空串 → `['00']`（全天空闲）。
- 状态条 12 节，每节 slot="01"~"12"，用 `occupied区间.includes(slot)` 判断占用（复刻 Flutter 的字符串 contains 技巧）。
- 改动：FreeRoomDto/FreeRoomSchema 加 seatNumber + occupied；real provider 加 `occupiedFromZyJc`；service 加
  `isValidNodeId`（4位数字 + 起止节 ∈[1,12] + 起始≤结束）；前端 rooms 页加起止节两个 picker + 座位数 + 点击展开状态条。
- 前端 picker value 是 index（startLesson-1），约束 onStart 时 end≥start、onEnd 时 start≤end。
- CI 全绿：70 项测试（6 领域 + 20 客户端 + 44 服务端）。真机回归待真实 zyjc 样本。

## 微信小程序：修复两个 UI bug（TDesign 样式隔离坑）

- Bug1：登录页「记住密码」开关被拉长。根因：`login/index.wxss` 的 `.remember view { flex: 1 }` 宽泛
  选择器穿透到 t-switch 组件内部（TDesign 组件 styleIsolation=apply-shared），把内部 view 拉伸。
  修复：文本容器加 `remember-copy` class，选择器改为 `.remember-copy { flex: 1 }`。
- Bug2：「我的」页 cell-group 宽度比其他窄。根因：TDesign `cell-group theme="card"` 自带
  `margin: 0 32rpx`（组件源码 cell-group.wxss），叠加 .page 的 32rpx padding 导致左右各缩进 32rpx。
  修复：用 externalClasses（`t-class`）传 `profile-cells`，页面 WXSS 覆盖 `.profile-cells { margin: 0 0 24rpx }`。
- **教训（长期）**：TDesign miniprogram 组件默认 styleIsolation=apply-shared，页面 WXSS 的宽泛元素选择器
  （如 `.xxx view`、`.xxx text`）会穿透到组件内部误伤内部元素。给组件旁元素写样式用明确 class；
  覆盖组件默认样式用组件 externalClasses（t-class），不要写宽泛后代选择器。

## 修正：profile cell-group 宽度/阴影（t-class 方案无效，改用内联 style）

- 之前 Bug2 用 `t-class="profile-cells"` + 页面 `.profile-cells { margin }` 覆盖组件 `.t-cell-group--card` 的 margin，
  **实际没生效**。根因：cell-group 是 apply-shared，页面 class 与组件内部 `.t-cell-group--card` 同为单 class 选择器，
  组件内部样式优先级更高，页面 class 覆盖不掉。
- 最终方案：给 t-cell-group 直接传**内联 style 属性**（`style="margin: 0 0 24rpx; box-shadow: ..."`），
  内联样式优先级最高，覆盖 margin 并补上 box-shadow（cell-group theme=card 默认无阴影，与其他 .card 不一致）。
- **教训补充**：apply-shared 组件，页面 class 样式无法覆盖组件内部同名 class，必须用内联 style（组件通用支持 style/customStyle 属性）
  或 !important。反过来，宽泛选择器（`.xxx view`）又会穿透误伤组件内部——两个方向都要小心。
